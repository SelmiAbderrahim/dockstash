# Аварийное восстановление

Этот сценарий покрывает случай «производственный VPS исчез». Он предполагает,
что уцелели только три вещи:

1. **VPS хранения** (с нетронутыми репозиториями restic).
2. **`MASTER_ENCRYPTION_KEY`** (сохранённый вне канала).
3. Сохранённый **конверт экспорта конфигурации**
   (`dockstash-export-*.json`).

Без всех трёх репозитории не восстановить — конверт экспорта бесполезен без
мастер-ключа, а мастер-ключ бесполезен без репозиториев хранения.

## 1. Поднимите свежий агент

Выделите чистый производственный VPS. Клонируйте репозиторий, заполните
`.env` и поднимите стек:

```bash
docker compose up -d
```

Службы `api`, `web`, `mongo`, `redis` и `docker-socket-proxy` стартуют на
пустой Mongo. Ни один проект пока не виден.

## 2. Предоставьте тот же `MASTER_ENCRYPTION_KEY`

Заполните `./secrets/master_encryption_key` побайтно тем же ключом от
старого агента. **Не генерируйте** новый — каждый шифротекст в конверте
экспорта привязан к этому ключу.

## 3. Импортируйте конверт экспорта

Войдите как пользователь с той же личностью, что и старый владелец, затем
отправьте POST сохранённого конверта на `/api/recovery/import`:

```bash
curl -X POST http://localhost:8080/api/recovery/import \
  -H "Authorization: JWT $TOKEN" \
  -H "Content-Type: application/json" \
  -d @dockstash-export-2026-07-01.json
```

Импорт валидирует форму конверта (`.strict()` zod), отказывает любому полю,
похожему на секрет в открытом виде, и расшифровывает каждый шифротекст
вашим мастер-ключом. Изменённый конверт или конверт, чью `keyVersion` этот
агент не может расшифровать, отклоняется с `HTTP 400`.

## 4. Подтвердите доступность хранилища

После импорта `restic snapshots` выполняется против репозитория каждого
проекта с расшифрованным паролем. Зелёный ответ подтверждает:

- VPS хранения доступен.
- Пароль расшифровывается под текущим `MASTER_ENCRYPTION_KEY`.
- Репозиторий не повреждён.

## 5. Восстановите

Запустите учение восстановления с панели или через планировщик. Снимки
восстанавливаются во временное рабочее пространство и сравниваются
побайтно/построчно с ожидаемыми метаданными.

## Инвариант трёх вещей

**Потеря мастер-ключа или кодов восстановления делает конверт экспорта
бесполезным.** Конверт несёт только шифротекст AES-256-GCM. Его безопасно
хранить вне сервера именно потому, что копия в чужих руках бесполезна без
ключа.

Храните `MASTER_ENCRYPTION_KEY` и коды восстановления на отдельных
носителях, в отдельных физических местах, и никогда в одной резервной копии
вместе с конвертом.
