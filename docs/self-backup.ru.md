# Самовосстановительная резервная копия

Оркестратор сохраняет **свою** Mongo в отдельный restic-репозиторий.
По умолчанию Compose использует постоянный том `self-backup-data`.

## Что сохраняется

- Документы `Project` (пути, план, шифрованные пароли репозиториев).
- Документы `Schedule` (cron, удержание, вид).
- Шифрованные секреты (SSH-ключ хранения, пароли restic
  репозиториев) — как шифротекст, никогда не в открытом виде.
- Строки истории резервных копий / проверок / учений.

Оркестратор передаёт `mongodump --archive` напрямую в
`restic backup --stdin` — временный файл не записывается.

## Зарезервированный репозиторий

Самосохранение пишет в `SELF_BACKUP_REPO` (значение Compose:
`/self-backup`). Том переживает пересоздание контейнеров, но остаётся на том
же хосте; для внешней защиты настройте удалённый URL restic и его учётные данные.

## Расписание

Каденция — `SELF_BACKUP_CRON` (по умолчанию ночью в `0 3 * * *`),
зарегистрирована рядом с другими cron-задачами. Повторная регистрация при
запуске идемпотентна — запись cron заменяется на месте, никогда не
складывается.

## Семантика отказа

Каждый прогон сохраняет строку `SelfBackupRun`: `running` → `success` при
записи, или `running` → `failed`, если какой-либо слой не удался.
Частичного `success` нет. Если `mongodump` не удался, `restic backup`
никогда не вызывается. Если `restic backup` не удался, поток архива
уничтожается. Отказ сохраняется в строке вместе с сообщением об ошибке.
