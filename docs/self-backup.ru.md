# Самовосстановительная резервная копия

Оркестратор делает резервную копию **своей** Mongo — проекты, расписания,
шифрованные секреты, история резервных копий — на VPS хранения в отдельный
restic-репозиторий, отличный от репозиториев пользовательских проектов.

## Что сохраняется

- Документы `Project` (пути, план, шифрованные пароли репозиториев).
- Документы `Schedule` (cron, удержание, вид).
- Шифрованные секреты (токен Polar, SSH-ключ хранения, пароли restic
  репозиториев) — как шифротекст, никогда не в открытом виде.
- Строки истории резервных копий / проверок / учений.

Оркестратор передаёт `mongodump --archive --oplog` напрямую в
`restic backup --stdin` — временный файл никогда не пишется. `--oplog`
гарантирует согласованность на момент времени по всем коллекциям.

## Зарезервированный репозиторий

Самосохранение пишет в `SELF_BACKUP_REPO` (по умолчанию `dockstash-self`) —
зарезервированный идентификатор, никогда не конфликтующий с проектом
пользователя. Пер-проектная очередь BullMQ (промпт 05) сериализует
одновременные тики cron против этого репозитория, чтобы restic никогда не
видел двух одновременных операций над одним репозиторием.

## Расписание

Каденция — `SELF_BACKUP_CRON` (по умолчанию ночью в `0 3 * * *`),
зарегистрирована рядом с другими cron-задачами. Повторная регистрация при
запуске идемпотентна — запись cron заменяется на месте, никогда не
складывается.

## Семантика отказа

Каждый прогон сохраняет строку `SelfBackupRun`: `running` → `success` при
записи, или `running` → `failed`, если какой-либо слой не удался.
Частичного `success` нет. Если `mongodump` не удался, `restic backup`
никогда не вызывается. Если `restic backup` не удался, поток архива
уничтожается. Отказ сохраняется в строке вместе с сообщением об ошибке.
