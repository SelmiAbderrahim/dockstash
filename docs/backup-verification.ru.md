# Верификация резервных копий

Резервная копия не считается доказанной, пока она не была восстановлена.
Dockstash доказывает это двумя способами:

## `restic check` — целостность структуры

Запускает `restic check` против репозитория. Выявляет отсутствующие
pack-файлы, повреждённые записи индекса и дрейф ссылок на блобы. Когда вы
передаёте `readDataSubset` (процент 1–100), Dockstash добавляет
`--read-data-subset=<pct>%`, чтобы restic фактически прочитал содержимое.

- `POST /api/backups/:id/check` по запросу.
- Планируется слоем очереди через `runScheduledChecks`.
- Сохраняет `lastCheckAt`, `lastCheckStatus` (`pass` / `fail`) и
  локализованный `lastCheckDetail`.
- `pass` требует нулевой exit-code — любой другой — `fail`.

## Учение по восстановлению — реальная гарантия

`restic check` доказывает, что репозиторий *корректно сформирован*. Только
восстановление доказывает, что он *восстанавливается*. `runRestoreDrill`:

1. Читает последний снапшот.
2. Восстанавливает его в изолированное scratch-пространство.
3. Побайтово хеширует каждый исходный путь против восстановленного зеркала.
4. Построчный diff каждого DB-слоя между восстановленным дампом и источником.
5. Суммирует расхождения. `pass` только при нуле.
6. Сохраняет `lastDrillAt`, `lastDrillStatus` и `lastDrillDetail`.
7. Убирает scratch в `finally`.

## Периодичность

- Проверка структуры: дешёвая; после каждого бэкапа + ежедневно.
- Учение: дорогое; минимум еженедельно на проект.
