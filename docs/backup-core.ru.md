# Ядро резервного копирования

Dockstash рассматривает каждый проект в `/var/www/<name>` как набор из
четырёх слоёв резервного копирования: файлы проекта, базы данных,
конфигурации обратного прокси и метаданные compose. Здесь описано, что
обнаруживает `scanProject` и как реально выполняется резервная копия.

## Что находит `scanProject`

Получая путь к проекту, `scanProject`:

1. Читает `<path>/docker-compose.yml`.
2. Проходит по каждому сервису. Для каждого `image` реестр адаптеров
   (`postgres`, `mysql`, `mariadb`, `mongo`) заявляет права на него и
   фиксирует слой базы данных с вычисленным именем контейнера и командой
   дампа исключительно в виде массива аргументов.
3. Отмечает пути конфигураций обратного прокси — `/etc/traefik` для образов
   Traefik и `/etc/nginx` для nginx.
4. Возвращает план `plan { paths, databases[], configs[] }`, который можно
   отредактировать в интерфейсе перед сохранением на проекте.

## Правило «сначала дамп, потом restic»

Файлы работающих баз данных **никогда** не копируются с диска. Для каждого
активного слоя базы данных Dockstash запускает
`docker exec <container> <dumpCmd>` и передаёт поток прямо в
`restic backup --stdin`. Флаги согласованности встроены в каждый адаптер:
`mysqldump --single-transaction`, `mongodump --oplog`, `pg_dumpall` к
живому серверу.

Каждая команда — это **массив argv** — никаких shell-интерполяций, никакого
`sh -c`. Значение переменной окружения `$(rm -rf /)` становится литеральным
токеном, а не подоболочкой.

## Белый список `/var/www/*`

Каждый путь — сам путь проекта, дополнительные пути в плане, значения из
API — проверяется по белому списку `/var/www/*`. Пустые строки, сегменты
`..`, байты NUL, символические ссылки-обходы и любые пути вне `/var/www`
отбрасываются до того, как их увидят restic или dockerode.

## Владение

Проекты ограничены пользователем. Любой маршрут `/api/backups` требует JWT,
и каждый ресурс проекта загружается через проверку владения, возвращающую
`403`, если вызывающий не владелец. Пароль репозитория Restic хранится в
записи проекта только как шифротекст AES-256-GCM; открытый текст
расшифровывается лишь в процессе на момент запуска и никогда не
возвращается клиенту.
