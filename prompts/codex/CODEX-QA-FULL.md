Use [@Browser](plugin://browser@openai-bundled) to run a single, all-in-one end-to-end QA pass across the entire Pulsy dashboard, starting from `http://localhost:3000/login` (`PUBLIC_WEB_URL`; the `pulsy-web` container via `WEB_PORT:80`; the tRPC/auth server is at `http://localhost:4000`). Use only the Codex builtin browser; if it fails, fix the Browser/runtime issue and retry rather than substituting Chrome, Playwright, or a host browser.

Log in with the seeded demo account `demo@pulsy.org` / `pulsy-demo-1234` (`make seed`); only register a new account (`/signup`) if that fails. Pulsy is a **single-user, self-hosted uptime monitor** — no multi-tenancy, organizations/workspaces, billing, tiers, or feature flags. Everything is always on and scoped to the logged-in user. The only public route is the status page `/status/$userId`; all else requires a session. Do not flag the absence of workspace switchers, plan badges, or feature-gated routes — none exist here.

Act as a rigorous QA engineer — the goal is a dashboard where every page works, not a report. Visit every page and sub-page; test every interaction (buttons, links, forms, dropdowns, filters, tabs, tables, pagination, modals) with both valid and invalid input. Cover the full surface:

- **Monitor list** (`/dashboard`) — must be a **table** (not card grid) with **inline** actions. Test quick add, full create, edit, delete, toggle-active, "check now", bulk-select, bulk pause/resume if present, and bulk delete (type-to-confirm `DELETE N`).
- **Bulk Add Monitors** — paste newline/space-separated URLs and test valid, invalid, duplicate, empty, mixed, and over-limit batches. Verify parsing, skipped/invalid feedback, localized validation, shared settings (method GET/HEAD/POST, interval >=30s, expected status, timeout, failure threshold, tags), disabled/pending states, no double-submit, successful batch close/toast behavior, immediate list/stat/query updates with no refresh, and that every created monitor is scoped to `ctx.user.id` and scheduled for checks.
- **Monitor detail** (`/dashboard/uptime/$monitorId`) — every tab: Overview (response-time chart, uptime bar, stats), Incidents (ongoing→resolved + duration), History (paginated check logs), Settings (URL, method GET/HEAD/POST, interval ≥30s, expected status, timeout, failure threshold), Notifications. Tab state must persist in the URL (`?tab=`) on refresh and deep-link.
- **Notification channels** — create/edit/delete/test for email, webhook, Slack, Discord, Telegram; verify flags (`notifyOnDown`/`notifyOnRecovery`/`notifyOnTlsExpiry`).
- **Email providers** — configure Resend, SendGrid, SMTP (each with `fromAddress`) + run "test"; secrets must never display unmasked (AES-256-GCM at rest) or appear in responses/console.
- **Public status page** — open `/status/$userId` logged out; confirm it shows only the owner's monitors/statuses with no auth-only data leaking.

Test every page across all dimensions before moving on:

1. **UI quality** — scrutinize pixel by pixel: no broken/overlapping/clipped layout, misalignment, inconsistent spacing/sizes/radii, off-center icons, broken images, FOUC, mismatched control heights, baseline drift. Flag missing loading/empty/error states, no pending/disabled state, missing post-action feedback, double-submission, dead links, no-op controls, and Uncodixify violations (card lift, `animate-pulse` on badges, shadow escalation, gradient text, `rounded-full`/`rounded-2xl`). Fix immediately, then re-test the same view.
2. **Functionality** — data loads and updates in place after every action (React Query invalidation + the uptime query-key factory, no manual refresh); badges (up/down/degraded), counts, lists, charts, uptime %, response times all update; tab state persists in URL; protected routes redirect to login (public status page does not); no console errors; tRPC succeeds or fails gracefully with toasts; every input Zod-validated with a localized error.
3. **Dark + light mode** — both themes on every page; colors from semantic tokens (`bg-card`, `text-foreground`, `bg-muted`), never hardcoded hex/rgb.
4. **Extreme responsive coverage** — check 320px, 360px, 390px, 430px, tablet, and desktop. On mobile, every page must be production-usable: tap targets >=44x44px, no horizontal overflow/clipping, no off-screen dialogs, no trapped scroll, table actions reachable, bulk toolbar usable, charts legible, forms comfortable, and text never overlaps adjacent controls.
5. **All five languages** — English, Arabic (RTL), French, German, Spanish: run the same core flows in each language, not just page-load checks. Confirm `lang`, `dir`, translations, missing keys, localized validation/toasts, untranslated/overflowing text, long German/French/Spanish labels, and full Arabic RTL (direction, mirrored icons, alignment).

For any defect, fix the root cause and rebuild via `make restart` (the web image is nginx-served, so changes need a rebuild; validate with Docker-first `make typecheck` / `make lint` / `make test` because `pulsy-web` is an nginx runtime and does not contain pnpm), then retry the same flow. While fixing: logical CSS props for RTL (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`), never `ml-*`/`mr-*`/`left-*`/`right-*` or `rtl:flex-row-reverse` (the app sets `dir="rtl"`, so flex reverses natively); add keys to all 5 locales under `apps/web/public/locales/{lang}/`; never put `min-h-[44px]`/`min-w-[44px]` on a Shadcn `Switch`.

**Zero-tolerance — do NOT stop while any of these is broken** (check `make logs` for scheduler/checker/notification failures):

- **Monitor checks** — creating schedules a monitor; "check now" runs an immediate HTTP check and records a log with response time + status. Never-running, hanging, or unrecorded checks are blocking.
- **Bulk creation** — bulk-added monitors appear immediately, inherit the chosen defaults, respect validation/caps, create no duplicates from duplicate input, are scoped to the logged-in user, and each starts checking on schedule.
- **Status & incidents** — crossing the failure threshold opens exactly one ongoing incident; recovery resolves it with computed duration; badges/lists reflect it in place.
- **TLS expiry** — HTTPS monitors extract and surface cert expiry; a TLS-check failure must be non-fatal to the HTTP check.
- **Notifications** — on a status change, all enabled channels dispatch per their flags; one channel failing must not block others; "test" reports a clear result.
- **Email providers** — Resend/SendGrid/SMTP config and "test" send work, secrets encrypted and never returned unmasked.
- **Public status page** — `/status/$userId` loads unauthenticated showing only that user's data.

**Never stop until every error is solved** — keep cycling (test, fix, rebuild, retry) across every page, interaction, both themes, all three sizes, and all five languages, until the dashboard passes every dimension with zero defects. Do not delete the data you create — leave all test monitors, channels, providers, and incidents in place.
